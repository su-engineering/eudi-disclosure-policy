# Threat model

## Assets and assumptions

- **The decision.** The main risk is a false `ALLOW`: a request passing preflight that asks for more than the purpose allows. A false `DENY` is an availability problem; a false `ALLOW` is a privacy failure.
- **The policy** is maintained by a trusted administrator and is trusted configuration.
- **The DCQL query** is untrusted. An attacker may control it, fully or partially, through application input.
- **Registration evidence** may be mislabeled by a faulty or careless integration.
- **The CLI** may process sensitive test material on developer machines and CI runners.
- The library never executes code from inputs and never makes requests.

## Threats and controls

| Threat                                                       | Controls                                                                                                                                                                                                  | Tests                                                                                                                                   |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **False pass from unverified registration data**             | Explicit evidence `state`; unverified evidence is never compared; verified evidence needs complete provenance, freshness, and matching relying-party context; no fallback. Documented as caller-asserted. | `TC-REG-*`, `TC-TIME-01`, property: evidence never improves a verdict                                                                   |
| **Alternatives hide excess claims**                          | Every selectable element of every credential set, optional set, claim set, and accepted type is evaluated. Set-level findings name the excessive option.                                                  | `TC-ALT-*`, property: per-element analysis equals branch enumeration; property: adding a forbidden alternative never improves a verdict |
| **Branch explosion**                                         | Element analysis is linear; branch enumeration is bounded by `maxBranches` and never yields `ALLOW` when exceeded. Option counts are budgeted (`maxSetOptions`).                                          | `TC-ALT-08`, `evaluate.test.ts`                                                                                                         |
| **Wildcard or parent selectors expand beyond the allowlist** | Conservative path relations; no guessed expansions; broad selectors are `INDETERMINATE` or `DENY`.                                                                                                        | `TC-PATH-*`, `TC-PURPOSE-03`, `path.test.ts`                                                                                            |
| **Format or schema confusion**                               | Exact format, type, namespace, and segment matching with strict types; no implicit conversion between SD-JWT and mdoc; unsupported formats are not interpreted.                                           | `TC-PATH-01`, `TC-PATH-04`, `SCN-C-03`, `TC-FORMAT-*`                                                                                   |
| **Unknown facts read as safe**                               | Unknown types, disclosure profiles, extensions, and formats are `INDETERMINATE` by default.                                                                                                               | Property: missing disclosure knowledge never yields `ALLOW`; `TC-EXT-*`                                                                 |
| **Extensions change semantics**                              | Unknown properties are preserved (analysis runs on the original input, not the parser's output) and flagged unless reviewed.                                                                              | `TC-BASE-03`, `TC-EXT-02`, `TC-EXT-03`                                                                                                  |
| **Prototype pollution and unsafe parsing**                   | Plain-data checks; `Object.hasOwn`; no merging of input into objects; `__proto__`, `constructor`, `prototype` rejected in policies and evidence; no `eval`.                                               | `policy.test.ts`                                                                                                                        |
| **Resource exhaustion**                                      | Byte, depth, count, path-segment, and option budgets checked before analysis; iterative traversal; cycles caught.                                                                                         | `evaluate.test.ts` resource limits                                                                                                      |
| **Sensitive data in logs**                                   | `values` never copied past normalization; findings carry counts and JSON types only; own error messages instead of platform parse errors; CLI never echoes input; file paths hidden by default.           | `TC-REDACTION-01`, property: values never appear, CLI tests                                                                             |
| **Timestamp manipulation**                                   | Caller-supplied strict UTC time; no clock reads in the core; evidence verified after the evaluation time fails.                                                                                           | `TC-TIME-01`, `primitives.test.ts`                                                                                                      |
| **Value type coercion**                                      | JSON types preserved; non-integer numbers in `values` rejected; path segments compared with strict types.                                                                                                 | `TC-VALUES-03`, `TC-PATH-04`                                                                                                            |
| **Network or environment access**                            | Lint rules forbid network, clock, randomness, environment, and `node:` imports in the core; the core compiles without Node.js types; the browser bundle runs in a bare realm.                             | `evaluate.test.ts` isolation, `tools/check-package.mjs`                                                                                 |
| **Dependency compromise**                                    | One runtime dependency, pinned exactly and audited; lockfile; Dependabot security updates; dependency review; CodeQL; npm provenance.                                                                     | CI, [ADR 0003](decisions/0003-dcql-parser.md)                                                                                           |
| **Misuse as a compliance certificate**                       | No badge or certified output; every document and the CLI state what `ALLOW` does not mean.                                                                                                                | Documentation review                                                                                                                    |

## Out of scope

- Compromise of the machine or process running the library.
- A malicious policy administrator.
- Correctness of the registration evidence's content once your code asserts it verified.
- Side channels of the evaluation's timing. Evaluation time depends on request size.
- Anything after the request leaves the verifier: wallet behavior, user consent, and the presentation response.
