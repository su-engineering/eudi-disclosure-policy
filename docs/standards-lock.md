## Known gaps and deliberate deviations

- **Registration evidence** is caller-asserted. No TS05 parser or signature verification exists; see [trust boundaries](trust-boundaries.md).
- **SD-JWT VC type inheritance** (OpenID4VP 1.0 Appendix B.3.5) is not resolved. A wallet may return a subtype of a requested `vct`. Policies need a rule per type; the engine never assumes a subtype is equivalent.
- **mdoc wildcards.** The original project specification lists "mdoc claim path with wildcard" as `INDETERMINATE`. OpenID4VP 1.0 §7.2 requires mdoc paths to be exactly two strings, so such a request is invalid DCQL and yields `DENY` with `DCQL_INVALID`.
- **Unknown credential types in alternatives.** The specification's §7.2 example expects `DENY`; its sample policy sets `unknownCredential` to `"indeterminate"`, which yields `INDETERMINATE`. Both block in strict CI. The [age-verification example](../examples/age-verification) uses `"deny"`.
- **Parser gaps.** @openeudi/dcql 0.3.0 accepts empty credential set options, duplicate claim paths, and non-integer `values`, and drops unknown top-level properties from its output. Supplemental checks reject the first three; analysis always uses the original input. See [ADR 0003](decisions/0003-dcql-parser.md).

## Update rule

A new OpenID4VP, ARF, or ETSI version is never adopted automatically, and never in a patch release. Adoption needs:

1. A new evaluation profile value (for example `openid4vp-1.1`), keeping the old one.
2. Fixtures for every behavioral difference, with clause references.
3. Migration notes and an entry in this file.
4. A minor or major release, and a `RULES_VERSION` bump if any rule's behavior changes.

A parser upgrade follows the same rule when it changes accepted input; the differential tests in `test/fixtures.test.ts` must stay green.
